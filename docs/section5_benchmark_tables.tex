\subsection{Software Performance on x86 Processors}
We provide two implementations for the x86 platform: a portable ISO~C99 reference implementation (\texttt{ref/}) and an AVX2-optimized implementation (\texttt{avx2\_weaver/}). The optimized build vectorizes NTT, base multiplication, compression, and parallel matrix generation for $n{=}256$ (\textsc{Weaver-512}, \textsc{Weaver-1024}); for \textsc{Weaver-2048} ($n{=}512$, $k{=}4$) it additionally enables AVX2 NTT in standard coefficient order, SHAKE128$\times$4 matrix sampling, fused \texttt{polyvec\_basemul\_acc}, and AVX2 modular reduction.

\subsubsection{Experimental Setup}
All measurements were taken on:
\begin{itemize}
  \item \textbf{Processor:} AMD EPYC 7C13 (x86-64), 2 logical CPUs (guest); firmware-reported nominal frequency 2.0\,GHz.
  \item \textbf{OS:} Linux (Debian), kernel \texttt{6.1.0-44-amd64}, 64-bit.
  \item \textbf{Compiler:} GCC 12.2.0, \texttt{-std=c99 -O3 -march=native -fomit-frame-pointer}.
  \item \textbf{ISA (AVX2 build):} \texttt{-mavx2 -mbmi2 -mpopcnt}.
  \item \textbf{Weaver flags:} \texttt{USE\_AVX\_NTT=1}, \texttt{USE\_AVX\_COMPRESS=1}, \texttt{USE\_GETRANDOM=1}; for mode~5 also \texttt{USE\_AVX\_FQ\_512=1}, \texttt{USE\_AVX\_GEN\_MATRIX512=1}. LTO enabled except on Keccak$\times$4 / rejection-sampling / selected compression units.
  \item \textbf{Timing:} \texttt{RDTSC} via \texttt{cpucycles}; medians over five consecutive runs ($N_{\mathrm{test}}{=}1000$ per run).
  \item \textbf{Weaver benchmark:} \texttt{avx2\_weaver/bench/bench\_components.c}.
  \item \textbf{ML-KEM benchmark:} pq-crystals Kyber \texttt{test/test\_speed*} (\texttt{avx2/}, commit \texttt{4768bd3}).
\end{itemize}
